# ТЗ для Cursor: пакет из 34 задач Treabo

Дата: 2026-07-04  
Режим работы: только локальный код. Не пушить, не коммитить, не поднимать dev-сервер без отдельной просьбы.

## 0. Контекст проекта

Проект разбит на несколько частей:

- `frontend/` - React web-клиент Treabo: публичные страницы, заявки, список заданий, карта, кабинет клиента.
- `mobile/` - Expo / React Native приложение мастера. Важно: часть экранов лежит в `mobile/screens/*`, часть служебного кода в `mobile/src/*`.
- `admin/` - Next.js админка, Proffi-разделы в `admin/src/pages/proffi/*`.
- `pixer-api/` - Laravel API. Основные маршруты Treabo/Proffi в `pixer-api/routes/proffi.php`.

Основные уже существующие API:

- `GET /api/proffi/categories`
- `GET /api/proffi/tasks`
- `POST /api/proffi/tasks`
- `GET /api/proffi/tasks/mine`
- `GET /api/proffi/tasks/{id}`
- `POST /api/proffi/tasks/{id}/applications`
- `GET /api/proffi/tasks/{id}/applications/preview`
- `GET /api/proffi/applications/mine`
- `GET /api/proffi/specialists`
- `GET /api/proffi/specialists/{id}`
- `GET /api/proffi/specialists/{id}/reviews`
- `POST /api/proffi/specialists/{id}/reviews`
- `POST /api/proffi/auth/phone/send-otp`
- `POST /api/proffi/auth/phone/verify-otp`
- `POST /api/proffi/auth/register`
- `POST /api/proffi/auth/verify`
- admin: `/api/proffi/admin/*`

Не изобретать параллельный API. Расширять существующий `proffi` контур.

## 1. Общие правила выполнения

1. Работать маленькими логическими пачками: API/migrations, web, admin, mobile.
2. Не удалять существующие фичи без необходимости.
3. Убрать моковые данные там, где задача требует реальные данные из Laravel.
4. Любые новые поля добавить через миграции, модели, мапперы API и UI.
5. Сохранить обратную совместимость: старые записи без новых полей не должны ломать списки.
6. Все пользовательские HTML-строки выводить как текст, не как HTML, если это не специально санитизированный rich text.
7. Проверка Cursor после реализации: минимум `npm run build --prefix frontend`, `npm run build --prefix admin`, `npm run start:web --prefix mobile` только если нужно проверить mobile web, и Laravel tests/`php artisan route:list` при доступности окружения. Сервер постоянно не поднимать.
